# Калькулятор лазерной резки и гибки

Веб-калькулятор стоимости лазерной резки и гибки листового металла. Клиент загружает чертёж `.dxf`, выбирает толщину, количество и гибку и сразу видит ориентировочную цену.

Сейчас это MVP: одна страница, без бэкенда, всё считается в браузере, файл никуда не отправляется. Полное ТЗ лежит в [`docs/TZ.md`](docs/TZ.md).

## Запуск

Нужен Node.js 24.

```bash
npm install
npm run dev        # локальный сервер, адрес появится в консоли
npm test           # тесты (Vitest)
npm run build      # прод-сборка в dist/
npm run lint       # линтер (oxlint)
```

Сайт публикуется на GitHub Pages автоматически при каждом пуше в `main` (`.github/workflows/deploy.yml`). Если линтер, тесты или проверка тарифов не проходят, сайт не обновляется. Собранный `dist/` можно выложить в любую папку любого сервера: пути в сборке относительные.

## Как обновить тарифы

Все цены хранятся только в [`data/tariffs.json`](data/tariffs.json). В коде цен нет.

1. Исправьте цены в `data/tariffs.json`. Цены указываются в рублях, не больше двух знаков после запятой.
2. Обновите `updatedAt` (формат `ГГГГ-ММ-ДД`). Эта дата показывается внизу страницы.
3. Запустите `npm test`. Файл проверяется схемой (`src/core/pricing/tariffs.ts`), и при ошибке тест покажет, какое поле не так.
4. Закоммитьте и запушьте в `main`, сайт обновится сам.

**Материал и резка** - `materials[]`:

- `workVariants` - варианты с теми же тарифами и дополнительным процентом к стоимости работ (`workSurchargePercent`).
- `densityKgM3` - плотность материала в кг/м³ (для стали - `7850`); используется для расчёта массы металла.
- `cutting.cutUnit` (`RUB_per_m`), `cutting.pierceUnit` (`RUB_per_piece`), `cutting.metalUnit` (`RUB_per_kg`).
- `cutting.rows` - одна строка на толщину:

| Поле | Что это |
|---|---|
| `thickness` | толщина, мм; список толщин в калькуляторе берётся отсюда |
| `cut` | резка, ₽ за 1 м |
| `pierce` | прожиг, ₽ за 1 шт. |
| `metal` | металл, ₽ за 1 кг (`null` - «по запросу», цену можно ввести вручную в форме) |

Строки идут по возрастанию толщины. Максимальная толщина резки - 10 мм: строки 12–16 мм из прайса не используются (решение Q-2).

**Гибка** - `bending`: цена за один гиб зависит от толщины, длины гиба и тиража.

- `thicknessBands` - диапазоны толщины. Толщина попадает в первый диапазон, где `толщина <= maxThickness`.
- `lengthRanges` - диапазоны длины гиба, правило то же: первый, где `длина <= maxLength`.
- `quantityBrackets` - колонки тиража: `min`–`max` гибов на весь заказ, `max: null` означает «без верхней границы».
- `lengthRanges[].prices` - для каждого id диапазона толщины массив цен по колонкам тиража, в том же порядке, что `quantityBrackets`.

**`null` вместо цены означает «по запросу».** Это не ноль: калькулятор показывает «по запросу» и помечает итог как неполный. Если строки нет целиком, вместо массива ставится `null`.

**Заказ** - `order`:

- `includeMaterialCost` - учитывать ли стоимость металла по умолчанию (`true`, решение Q-11, отменяет Q-7). При `true` в форме доступны переключатель «Наш металл / Металл заказчика» и поле «Цена металла, ₽/т».
- `marginMm` - технологический отступ с каждой стороны габарита детали при расчёте массы металла, мм (сейчас `5`).
- `sheetLayout` – размеры листа (`widthMm`, `heightMm`), отступ от края (`edgeMarginMm`), зазор между деталями (`partGapMm`) и разрешение поворота на 90° (`allowRotation`).
- `minOrderRub` - минимальная сумма заказа в рублях (сейчас 5 000). Если полный итог ниже, калькулятор показывает предупреждение, но сумму не поднимает (решение Q-8). `null` - минимума нет.
- Разовая наладка и подготовка УП не учитываются (решение Q-10).

Итог округляется **вверх до целого рубля** (решение Q-9), сумма «За деталь» показывается с копейками. Внутри все деньги хранятся в копейках.

## Как устроен код

```
src/core/      расчёт без React и браузера - позже переиспользуется на сервере
  dxf/         разбор DXF: длины, контуры, прожиги, габарит, предупреждения
  pricing/     тарифы (zod-схема), резка, гибка, итог, текст расчёта
src/ui/        компоненты страницы
data/          tariffs.json
tests/         тесты и эталонные чертежи (tests/fixtures)
```

Внутри размеры хранятся в миллиметрах, деньги в копейках (целые числа). В рубли суммы переводятся только при показе.
