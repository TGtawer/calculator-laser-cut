# ТЗ: калькулятор стоимости лазерной резки и гибки металла

Версия 0.1 · 2026-11-17 · автор: Никита

## 1. Цель

Клиент сам загружает чертёж детали (.dxf), выбирает толщину, количество и параметры гибки и сразу видит ориентировочную стоимость. Резчику не нужно тратить время на расчёт.

**Текущий этап — MVP для тестирования.** Это отдельный проект без бэкенда: всё считается в браузере, тарифы берутся из `data/tariffs.json`.

**Перспектива.** Калькулятор будет продаваться другим цехам лазерной резки как сервис (SaaS). Поэтому логика расчёта уже сейчас пишется отдельным модулем без привязки к UI (см. раздел 9).

## 2. Пользовательский сценарий (MVP)

1. Клиент открывает страницу калькулятора.
2. Загружает один файл `.dxf` (перетаскиванием или кнопкой).
3. Видит превью детали (контуры в SVG), габарит, длину реза, число прожигов и предупреждения, если они есть.
4. Выбирает:
   - материал (пока один вариант — «Сталь горячекатаная и холоднокатаная»);
   - толщину — выпадающий список строго из `tariffs.json`, свободный ввод запрещён;
   - количество деталей (целое ≥ 1);
   - гибку: чекбокс «Нужна гибка», затем число гибов на деталь (целое ≥ 1) и длину гиба в мм (одно значение для всех гибов в MVP).
5. Видит расчёт (раздел 5) с разбивкой по статьям. Если итог ниже минимальной суммы заказа, показывается предупреждение.
6. Может нажать «Скопировать расчёт», чтобы получить текст в буфер для отправки в мессенджер или на почту.
7. Внизу всегда показана подпись: «Расчёт ориентировочный. Окончательную стоимость подтвердит менеджер после проверки чертежа».

Пересчёт происходит мгновенно при любом изменении параметров. Отдельной кнопки «Рассчитать» нет.

## 3. Разбор DXF

### 3.1 Входной файл
- Формат: ASCII DXF. Бинарный DXF и DWG не поддерживаются. Для них нужно сообщение «Сохраните чертёж в формате DXF (ASCII)».
- Максимальный размер 10 МБ.
- Одна деталь на файл. Если внешних (не вложенных) контуров больше одного, выводится предупреждение `MULTIPLE_PARTS`: «В файле, похоже, несколько деталей — расчёт идёт как за одну».

### 3.2 Единицы измерения
Единицы берутся из `$INSUNITS` в HEADER. Внутри всё хранится в мм.

| $INSUNITS | Единица | Множитель в мм |
|---|---|---|
| 4 | мм | 1 |
| 5 | см | 10 |
| 6 | м | 1000 |
| 1 | дюйм | 25.4 |
| 0 / нет | не задано | 1 + предупреждение `UNITS_ASSUMED_MM` |

Иначе: ошибка «Неподдерживаемые единицы чертежа».

Дополнительная проверка: если габарит меньше 1 мм или больше 6000 мм, выводится предупреждение `SUSPICIOUS_SIZE` («Проверьте единицы чертежа»).

### 3.3 Учитываемые объекты и длина

| Объект | Длина |
|---|---|
| LINE | расстояние между точками |
| CIRCLE | 2πr |
| ARC | r · Δθ, где Δθ — угол против часовой стрелки от начального к конечному, нормализованный в (0, 2π] |
| LWPOLYLINE / POLYLINE (2D) | сумма сегментов; сегмент с bulge `b ≠ 0` — это дуга: θ = 4·atan(\|b\|), r = c / (2·sin(θ/2)), длина = r·θ, где c — хорда; если флаг closed, учитывается и сегмент «последняя → первая вершина» |
| ELLIPSE | численное интегрирование по параметру (≥ 360 шагов) с учётом start/end параметра |
| SPLINE | вычисление кривой по алгоритму де Бура (control points + knots + degree), сэмплирование ≥ 200 точек; если есть только fit points — ломаная по ним |
| INSERT (блок) | развернуть содержимое блока с учётом смещения, масштаба и поворота; вложенные блоки обрабатываются рекурсивно |

**Игнорируются:** TEXT, MTEXT, DIMENSION, HATCH, POINT, LEADER, MLEADER, VIEWPORT, а также объекты на слоях, которые пользователь отключил в UI. Под превью показывается список слоёв с чекбоксами, по умолчанию все включены.

**Точность длины:** ±0.5 % для сплайнов и эллипсов, ±0.01 мм для остального.

### 3.4 Контуры и прожиги
- Каждый CIRCLE, замкнутая полилиния, полный эллипс и замкнутый сплайн считаются одним замкнутым контуром.
- Остальные элементы (LINE, ARC, незамкнутые полилинии и т.п.) склеиваются в цепочки по совпадению концов с допуском **0.01 мм** (константа в конфиге).
  - Если концы цепочки сошлись, это замкнутый контур.
  - Если нет, это незамкнутый контур. Он тоже даёт 1 прожиг и предупреждение `OPEN_CONTOUR` («В чертеже есть незамкнутые контуры — проверьте файл»).
- **Число прожигов = число замкнутых контуров + число незамкнутых.**
- Полностью совпадающие дубли элементов (частая ошибка в DXF) удаляются до расчёта. Выводится предупреждение `DUPLICATES_REMOVED` с их количеством.
- Внешние и внутренние контуры определяются по вложенности: контур A внутри B, если bbox A лежит внутри bbox B и точка A попадает внутрь полигона B. Это нужно для `MULTIPLE_PARTS` и для превью: внешний контур рисуется одним цветом, отверстия другим.

### 3.5 Результат разбора
```ts
type DxfAnalysis = {
  cutLengthMm: number;
  closedContours: number;
  openContours: number;
  pierces: number;
  outerContours: number;
  bbox: { minX: number; minY: number; width: number; height: number }; // мм
  layers: string[];
  contours: Contour[];          // для превью: массив полилиний (точки в мм) + isOuter
  warnings: WarningCode[];
};
```

## 4. Тарифы

Источник — `data/tariffs.json`. Описание полей там же, в `notes`. Исходные скриншоты прайса лежат в `docs/source/`.

- **Резка:** цена за 1 м реза и за 1 прожиг, отдельная строка для каждой толщины от 0.5 до 10 мм. Максимальная толщина резки — 10 мм (решение Q-2).
- **Гибка:** цена за 1 гиб. Зависит от трёх параметров: диапазона толщины (t1…t5), диапазона длины гиба (L1…L4) и тиража гибов (q1…q5).
- Значение `null` означает, что цены нет. Тогда калькулятор показывает «по запросу» и итог помечается «не полный».

Код загружает JSON и валидирует его схемой (zod). Ошибка валидации ломает сборку или тесты, но не UI в рантайме.

## 5. Формулы

Обозначения: `L` — длина реза одной детали в метрах, `P` — прожигов на деталь, `t` — толщина, `N` — количество деталей, `B` — гибов на деталь, `Lb` — длина гиба в мм.

```
rowCut        = строка cutting.rows с thickness == t
cutPerPart    = L × rowCut.cut
piercePerPart = P × rowCut.pierce

totalBends    = B × N
band          = первый thicknessBands, где t <= maxThickness      (t > 8 → «по запросу»)
range         = первый lengthRanges, где Lb <= maxLength          (Lb > 3200 → «по запросу»)
bracket       = quantityBrackets, где min <= totalBends <= max
bendPrice     = range.prices[band.id][индекс bracket]             (null → «по запросу»)
bendPerPart   = B × bendPrice

pricePerPart  = cutPerPart + piercePerPart + bendPerPart
total         = pricePerPart × N
totalRounded  = округление total вверх до целого рубля

если order.minOrderRub задан и totalRounded < order.minOrderRub → предупреждение
```

**Деньги.** Внутри расчёт идёт в копейках целыми числами, чтобы не было ошибок float. Каждая статья за штуку округляется до копеек. Итог округляется вверх до целого рубля и показывается без копеек (Q-9); сумма «За деталь» показывается с копейками. Если задана минимальная сумма заказа (сейчас 5 000 ₽) и полный итог ниже неё, показывается предупреждение, но итог не поднимается автоматически (Q-8). Для неполного итога проверка минимума не выполняется: неизвестные статьи могут его поднять.

### 5.1 Контрольные примеры (обязательны как unit-тесты)

**Пример 1** — `tests/fixtures/01_plate_rect_2holes.dxf`, сталь 3 мм, 10 шт, без гибки:
- L = 0.362832 м, P = 3
- рез: 0.362832 × 113 = 41.00 ₽
- прожиги: 3 × 21 = 63.00 ₽
- за деталь 104.00 ₽, **итого 1 040 ₽** (ниже минимума 5 000 ₽ — предупреждение)

**Пример 2** — `tests/fixtures/02_slot_lwpolyline_bulge.dxf`, сталь 5 мм, 4 шт, без гибки:
- L = 0.388496 м, P = 2
- рез: 0.388496 × 150 = 58.27 ₽
- прожиги: 2 × 26 = 52.00 ₽
- за деталь 110.27 ₽, **итого 442 ₽** (441.08 ₽ округляется вверх; ниже минимума — предупреждение)

**Пример 3** — только гибка (без DXF, тест функции `bendingCost`): t = 3, Lb = 800, B = 2, N = 10:
- totalBends = 20 → q1; band t3; range L2 → 55 ₽/гиб
- за деталь 110.00 ₽, **итого 1 100 ₽** (ниже минимума — предупреждение)

**Пример 4** — гибка с отсутствующей ценой: t = 8, Lb = 2000 → range L3, band t5 → `null` → «по запросу», итог помечен «не полный». Резка в итоге считается по тарифу 8 мм (233 ₽/м, 30 ₽/прожиг). Итог по известным статьям — 2 630 ₽; проверка минимума для неполного итога не выполняется.

**Пример 5** — граничные случаи: t = 2.5 → t3; Lb = 500 → L1; Lb = 501 → L2; totalBends = 50 → q1, 51 → q2, 1001 → q5.

## 6. Интерфейс

- Язык — русский. Валюта ₽, разделитель тысяч — пробел, десятичный — запятая (`Intl.NumberFormat('ru-RU')`).
- Итог — целыми рублями, сумма «За деталь» — с копейками. Если итог ниже минимальной суммы заказа, показывается предупреждение.
- Одна страница, адаптивная, корректно работает на телефоне от 360 px.
- Блоки: «Чертёж» (загрузка, превью, слои, предупреждения) → «Параметры» → «Расчёт».
- Оформление сдержанное: графит + красный акцент, без анимаций ради анимаций.
- Ошибки разбора показываются по-человечески, без стек-трейсов.

## 7. Нефункциональные требования

- Без бэкенда: файл не покидает браузер.
- Разбор DXF на 5 МБ — не дольше 2 с на среднем ноутбуке. При необходимости разбор выносится в Web Worker.
- Покрытие тестами модуля `core/` — все примеры из 5.1 и все три фикстуры из `tests/fixtures/expected.json`.

## 8. Решённые вопросы

Все вопросы закрыты 2026-11-21.

| № | Вопрос | Решение |
|---|---|---|
| Q-1 | Что означает звёздочка в строках 10–16 мм (300/330* и т.п.)? | Звёздочку не учитываем: в расчёте используются значения без неё. Для 10 мм это 300 ₽/м и 33 ₽/прожиг. Строки 12–16 мм убраны из тарифов. |
| Q-2 | Максимальная толщина резки — 10 или 16 мм? | 10 мм. Строки 12–16 мм из `tariffs.json` удалены. |
| Q-3 | Таблица гибки: заголовок первого блока длины и строки «до 1», «1–2», «3–4» обрезаны; в блоке 1500–2500 обрезаны строки 5–6 и 7–8 | Решено 2026-11-21: получен полный прайс. |
| Q-4 | В какой диапазон гибки попадают толщины между 2 и 3 мм (2.5)? | Толщина округляется вверх: 2.5 мм попадает в «3–4». |
| Q-5 | Тираж гибки считается по всем гибам заказа или по гибам на деталь? | По всем гибам заказа (B × N). |
| Q-6 | Границы длины гиба: 500 мм — это «до 500» или «от 500»? | «До 500» включительно. |
| Q-7 | Учитывать ли стоимость металла? | Нет, только услуги. |
| Q-8 | Есть ли минимальная сумма заказа? | Да, 5 000 ₽. Если полный итог ниже, показывается предупреждение; сумма не поднимается автоматически. |
| Q-9 | Как округлять итог (до рубля, до 10 ₽)? | До рубля, всегда вверх. Сумма «За деталь» показывается с копейками. |
| Q-10 | Есть ли разовая стоимость наладки или подготовки УП? | Нет. |

## 9. Этапы

**Этап 1 — MVP (текущий).** Всё из разделов 2–7.

**Этап 2 — расширение.**
- Несколько позиций в одном расчёте (разные DXF, толщины, количества) с общим итогом.
- Гибы разной длины в одной детали; определение линий гиба по отдельному слою DXF.
- Стоимость металла (лист × цена за кг/м²), минимальный заказ.
- Выгрузка коммерческого предложения в PDF, отправка заявки на почту или в Telegram.

**Этап 3 — SaaS для других цехов.**
- Бэкенд и БД: цеха (tenants), пользователи, тарифы каждого цеха, заявки.
- Админка цеха: редактирование тарифов в той же структуре, что `tariffs.json`, свои материалы и толщины, логотип и контакты.
- Встраиваемый виджет (iframe или script) на сайт цеха плюс отдельная ссылка-страница.
- Подписка и оплата, лимиты по тарифному плану.
- Модуль `core/` переиспользуется без изменений: в браузере для мгновенного расчёта и на сервере для проверки расчёта в заявке.
