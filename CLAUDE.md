# CLAUDE.md — калькулятор лазерной резки и гибки

## О проекте
Веб-калькулятор стоимости лазерной резки и гибки листового металла. Клиент загружает DXF, выбирает толщину, количество и гибку и получает ориентировочную цену.
Сейчас — **MVP для тестирования**: одна страница, без бэкенда, всё считается в браузере.
В будущем — SaaS для разных цехов, поэтому логика расчёта отделена от UI.

Полное ТЗ: `docs/TZ.md`. **Прочитай его перед началом работы.**
Тарифы: `data/tariffs.json`. Исходные скриншоты прайса: `docs/source/`.
Тестовые чертежи и эталоны: `tests/fixtures/`.

## Стек
- Vite + React + TypeScript (strict)
- `dxf-parser` — разбор ASCII DXF
- `zod` — валидация `tariffs.json`
- Vitest — тесты
- Стили: CSS Modules или обычный CSS, без UI-китов


## Правила
1. **Если требование неясно или противоречиво — спроси Никиту, не додумывай.** Не меняй уже принятые решения без согласования.
2. **Цены — только из `data/tariffs.json`.** Никаких захардкоженных чисел в коде. Значения тарифов не меняй сам. Если видишь ошибку — сообщи.
3. `null` в тарифах означает «по запросу». Это не ноль и не ошибка: итог помечается как неполный.
4. `src/core/` не зависит от UI и браузера, чтобы позже переиспользовать его на сервере.
5. Внутри все размеры в мм, деньги в копейках (целые числа). Перевод в рубли — только при отображении.
6. По открытым вопросам из ТЗ (раздел 8) реализуй вариант «по умолчанию» и ставь `// TODO(Q-n)` рядом.
7. Каждая формула покрыта тестом. Контрольные примеры из ТЗ 5.1 и все фикстуры из `tests/fixtures/expected.json` обязаны проходить.
8. Перед тем как считать задачу выполненной: `npm test` и `npm run build` без ошибок.
9. Интерфейс и сообщения пользователю — на русском. Комментарии в коде — на русском, имена в коде — на английском.
10. Новые зависимости добавляй только при реальной необходимости и называй их в отчёте.

## Порядок реализации MVP
1. Каркас проекта (Vite + TS + Vitest), zod-схема и загрузка `tariffs.json`.
2. `core/dxf`: длины сущностей → контуры → `analyze`. Тесты на фикстурах.
3. `core/pricing`: резка, гибка, итог. Тесты на примерах из ТЗ 5.1.
4. UI: загрузка → превью → параметры → результат.
5. Ошибки и предупреждения, адаптив под телефон, «Скопировать расчёт».
6. Короткий README: как запустить и как обновить тарифы.
